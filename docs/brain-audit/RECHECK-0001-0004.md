## 0002 — runner liveness (P2) — VERIFIED

- **Base** (`a0f1faf`): a 7-day-old IDLE heartbeat, a missing heartbeat and a future heartbeat all return `healthy: true`, `tone: green`, `DATA CURRENT · RUNNER IDLE`. Independent reproduction of the defect, including the two malformed-input contract probes.
- **Repaired UI** (`topbar.js::runnerLivenessViewModel` + `systemHealthViewModel`) on 10 adversarial payloads: green **only** for a server verdict that says `CONFIRMED_ALIVE` with `alive_confirmed === true` and a consistent `age_seconds <= tolerance_seconds`. `CONFIRMED_ALIVE` with a missing/false flag, or with `age > tolerance`, or an absent verdict, or a bogus state name, all fail safe to amber `LIVENESS UNKNOWN`; `STALE_UNCONFIRMED`, `CLOCK_INCONSISTENT`, `FAILED` and `STOPPED` get their own labels. The green path still exists (it is not "amber forever").
- **Repaired backend** (`forward_testing/runner_health.py::assess_runner_health`, exercised directly, not through the project's tests): 30 s → `CONFIRMED_ALIVE`; 359 s → `CONFIRMED_ALIVE`; 361 s → `STALE_UNCONFIRMED`; 604800 s → `STALE_UNCONFIRMED`; future → `CLOCK_INCONSISTENT`; `last_error`/`ERROR` → `FAILED`; `STOPPED` → `STOPPED`; unknown status → `UNCONFIRMED`; no heartbeat → `NEVER_RUN`. A trusted observed cadence of 600 s widens the tolerance to 1800 s (`tolerance_source=observed_heartbeats`), while a single sparse gap does not.
- Input hardening: operator tolerance accepts only integers 1…86400 — `0`, `-1`, `86401`, `True`, `1.5` and `"600"` are all refused with `ValueError`; a naive `recorded_at` is refused (`TypeError`) instead of being silently interpreted.

Evidence: [`evidence/recheck-0002-runner-liveness.txt`](evidence/recheck-0002-runner-liveness.txt). Residual note: the fix deliberately still refuses a same-timeframe engine fallback when the viewed evidence is `available: false` (case E).
